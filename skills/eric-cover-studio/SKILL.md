# Eric 自媒体封面工作室

目标：让人一眼读懂本期对象、Eric 的判断和情绪，得到能直接发布的图片；下一期无需重新解释全部审美。

## 先读什么

- 新一期：读 [审美依据](references/aesthetic-profile.md)、[流程与提示词](references/workflow-and-prompts.md)，按题材选3–5张相关参考。
- 改已有封面：先查看用户指向的图片和原始素材，再读 [修改案例](references/casebook.md) 中相关条目。保留已确认部分，明确本轮修改项。
- 主视觉已选定、只出其他尺寸：读 [尺寸与构图](references/layouts-and-sizes.md)，无需重做标题研究。
- 助理版的原图、原始XLSX、历史喜欢的成品和浏览页：见 [素材位置](references/private-assets.md)。公开版无原图时，使用 [样本索引](references/reference-index.md) 和文字反馈；不要声称看过未加载的图片。

## 判断依据

优先采用本次用户要求和本期已确认的图／文字；再参考Eric原始反馈与明确喜欢的历史作品；母版文档和本技能的归纳提供候选方法。当前指令可以改变旧偏好。

原始横版反馈见 [38条反馈](references/horizontal-feedback.tsv)；[历史原话](references/feedback-ledger.md) 保留修正的适用范围。竖版60张是Eric主动筛选的“觉得还不错”的参考集，没有逐图评级。文件名里的“终稿”、AI的质量检查和已经打包，均不能代替Eric认可。

## 每期执行

1. **建立本期输入。** 获取视频主题／最终判断、真实作品素材、本期Eric截图或明确不用人物、所需比例和输出位置。用 [输入卡](assets/brief-template.md) 记录；已有信息直接复用。前采中的曲名、游戏关键词和风格判断要与成片核对，不能只看标题猜内容。
2. **选标题和视觉方向。** 默认提供少量标题与2–3个有实质区别的方向；已经指定标题或定稿时直接执行。字体、人物表情、题材背景必须服务同一个观点。放大标题，优先修正普通、无特点或难读的字形。
3. **制作主画幅。** 默认先16:9。查看原始图片后再编辑；使用环境提供的图像编辑／生成工具、设计工具或可编辑的排版工具。保留本期人物身份、耳机、轮廓和表情，题材素材有来源。不凭空画一个类似游戏的背景冒充实景；生成式参考改作要如实记录。缺少必要素材时先完成可做的标题与构图，指出缺口。
4. **展示并承接反馈。** 交付真实图片供选择。沿用“先给我看16:9，确认后再适配”的惯例；用户已选择图、明确要求同一方向全部尺寸或直接批量出图时，按已有授权完成，不重复确认。一次主要解决当前失败点；旧版另存保留。
5. **独立重排其他比例。** 常用16:9 = 1920×1080、4:3 = 1600×1200、3:4 = 1080×1440。比例来自Eric的固定需求；像素值是已用交付标准，不是平台官方规定。具体项目指定尺寸时以项目为准。竖版重排标题、人物和关键词，避免直接裁切、拉伸或填黑边。
6. **交付前检查。** 查看最终导出文件及手机缩略图，逐字核对中文／曲名，检查标题边缘、脸与文字遮挡、背景题材、人物真实性、自然轮廓、铺满画面和实际像素。技术检查脚本见下方。质量检查与Eric审批分别记录。
7. **交付与沉淀。** 交付版本化图片和相对路径导出记录；需要ZIP时检查包内图片。请求可编辑版时交付独立文字／背景／人物层或工具支持的真实编辑源，不将扁平PNG说成分层工程。新反馈记录原话、版本、日期和适用范围，另存补充记录，不改写原始XLSX，不把一次修正扩大成全账号禁令。

## 不可遗漏的审美判断

- **大字有设计，缩小能读。** Eric喜欢特征明确的艺术展示字、宋体、手写与有完成度的大标题。不能把“更潮”简化成普通黑体加粗倾斜；也不能把所有无衬线字体一概禁用，S级参考中有多种字形。
- **图文和情绪统一。** 真实截图、作品身份、人物姿态与标题要一致；“惊讶”“陶醉”“判断”因题材而变。
- **内容真实，人物清楚。** 优先本期截图；无本期合适素材时，经本次任务选择使用通用授权照片或无人物方案，不默默换成其他期人物。被电脑挡住的身体可自然裁切，不补出假肢、破损耳机和模糊轮廓。
- **丰富也要统一。** 对比、曲目合集、教程可以用多素材，但每块承担内容意义。单一背景要求适用于用户指定的项目；普通Reaction可优先一张主背景。无理由的分屏、解释海报、小字与装饰贴纸会削弱主张。
- **配色随题材。** 蓝金、紫色、复古暖色、黑白等都是可选，不绑定一套霓虹模板或照搬其他业务的品牌色。

## 技术检查

使用 [导出记录模板](assets/export-manifest-template.json)，将文件名、期望尺寸、审批与人工／视觉检查字段填写为本期事实。模板中的空值保持待填，不能预先标成通过。

```bash
python3 scripts/check_exports.py /path/to/episode/export-manifest.json --report /path/to/episode/technical-qa.json
```

脚本仅检查PNG结构、尺寸、比例、SHA-256、可选ZIP内容和旧文件哈希；不能判断画面审美、语义、真人一致性或用户审批。需要检查其他格式时用相应工具。本技能不要求全局安装图像环境，也不自行对外发布或上传GitHub。
